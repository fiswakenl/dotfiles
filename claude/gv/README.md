# GV: голос для Claude Code

Говоришь — реплика уходит в окно Claude. Продолжение или поправка к уже переданному стирает старый ход из истории Claude и отправляет склеенный текст; новая мысль, пока Claude занят, — быстрый вопрос веткой разговора (quick), основная работа не прерывается.

## Как слышит

```
микрофон ──звук──▶ цикл разговора LiveKit ─┬─ распознавание: Deepgram (nova-3) | OpenAI ─┐
                                           ├─ детектор речи (локальный)                  ├─▶ реплики ──▶ OpenAI Decisions ──▶ ядро ──▶ окно Claude
                                           └─ модель конца реплики (локальная) ──────────┘
```

Разговор ведёт готовый цикл LiveKit Agents (`AgentSession`) — как библиотека, без сервера, комнаты и аккаунта LiveKit: детектор речи, поток распознавания, сбор кусков текста, конец реплики. Связь с распознаванием пропала (сон мака, сеть) — поток открывается заново сам, пока не подключится; Deepgram ходит напрямую, без прокси.

Реплика кончается по тишине: речь стихла — локальная модель по звуку оценивает, договорил ли человек. Уверена — реплика закрывается через 0,8 с тишины, не уверена — через 2,5 с (`GV_PAUSE_MS`). Порог и паузы подобраны на записях диктовки — `tests/loop_bench.py`.

Куда реплику, решает классификатор OpenAI Decisions (~0,2 с), вопрос да или нет: продолжает ли она последнюю переданную. Да — откат и склеенный текст; нет — новая мысль: пока Claude занят — quick, свободен — новое сообщение. Текст уходит как распознан.

Тот же вопрос задаётся и раньше конца фразы: пока Claude работает над последней репликой, а человек заговорил снова, классификатор по первым словам (и заново на каждом новом куске) отвечает, продолжение ли это. Да — ход Claude останавливается сразу; фраза договорена — решение заново по всему тексту: продолжение — откат и склейка, новая мысль — прерванный запрос уходит заново, а мысль — quick.

## Запуск

```zsh
ccg            # Claude с GV и мостом отката (функция в ~/.config/zsh/20-projects.zsh)
/gv            # включить или выключить голос; состояние — ~/.claude/gv.state
```

Чем распознавать речь — `/gv:deepgram` (по умолчанию) или `/gv:openai` (gpt-live-transcribe по сокету Realtime, через `HTTPS_PROXY`): команда пишет выбор в `~/.claude/gv.ears` и гасит сервис, плагин поднимает его заново. Дальше всё одинаково; в OpenAI уходит только речь — он берёт за каждую секунду звука.

`ccg` = `--plugin-dir ~/.claude/gv` + `BUN_OPTIONS=--preload=…/preload.mjs`. Preload нужен мосту: штатный API плагина не даёт откатить историю.

Ключи: Deepgram — `~/.config/deepgram.env`, OpenAI — `~/.config/openai.env` (через `HTTPS_PROXY`).

## Как устроено

- `listen.py` — слух: микрофон → цикл LiveKit (распознавание, конец реплики) → вопросы к Decisions, решение, куда реплика. Правила — в его шапке.
- `core.py` — запросы к Claude: ask, quick, поправки, откаты, остановка хода. Правила — в его шапке.
- `voice.py` — сервис: HTTP-ручки (список — в его шапке), страница журнала `page.html`, плашка `overlay.swift` поверх экрана (мак: последние сообщения сессии пузырями; собирается в `.build/`).
- `journal.py` — `~/.claude/gv.log` и запись каждого запуска в `~/.claude/gv-trace/` (события с точным временем и звук в WAV, последние 20).
- `devtools/` — как вопросы к Decisions делят записанную диктовку (конец реплики там — прежним вопросом по тексту, слух закрывает её моделью по звуку): текст как был, без знаков и звук заново через Deepgram, варианты вопроса правятся на странице и сразу прогоняются. `uv run --script devtools/server.py` → http://127.0.0.1:8791 (страница собрана в `web/dist`; правка — `npm run dev` в `devtools/web`, :5191).
- `decisions_view.py` — страница по отрезку записи: шкала со звуком, текстом Deepgram, вопросами к Decisions и запросами Claude, легенда со значениями под курсором, лог событий, проигрыватель.
- `hooks/register.ts` — плагин: забирает работу `/next` — ask шлёт в окно Claude через мост (командами `/call` сервиса), quick — веткой разговора, cancel — останавливает ход; ответ — `/answer`. О каждом ходе Claude, и набранном руками, сообщает сервису: пока ход идёт, новый ask ждёт в ядре. Номера запросов — номера одного запуска сервиса (заголовок `X-GV-Epoch`): после перезапуска плагин их забывает, а сервис отвергает старые.
- `preload.mjs` + `native/bridge.mjs` — мост в окно Claude: `status`, `list`, `send`, `rewind`, `cancel` (остановить идущий ход, как Esc). Сокет `$TMPDIR/gv-UID/PID.sock`, свой у каждого процесса.

## Снаружи

Один вход — `POST /call {"name", "args"}`:

```sh
curl -s localhost:8790/call -d '{"name":"ask","args":{"text":"Что в todo?"}}'
curl -s localhost:8790/call -d '{"name":"rewind","args":{"target":1}}'
curl -s localhost:8790/call -d '{"name":"list"}'                              # мост: сообщения в окне Claude
```

## Проверки

```sh
uv run --script ~/.claude/gv/tests/core_test.py    # сценарии на ядре, пара секунд
claude plugin test ~/.claude/gv                     # плагин вокруг ненастоящего сервиса
uv run --script ~/.claude/gv/tests/trace_demo.py    # живой прогон на речи из say: Deepgram и Decisions, платно, и страница по нему
uv run --script ~/.claude/gv/tests/loop_bench.py     # замер слуха на записях диктовки: концы реплик и закрытия посреди мысли; команды — в шапке
```

Мост — внутренний механизм, проверен на Claude Code 2.1.317–2.1.321, macOS arm64: экран Claude он находит по записи в таблицу Ink, а не по имени внутреннего файла, но после обновления Claude preload всё же может потребовать правки.
