DVC (3.x): стадии в `dvc.yaml` (cmd, deps, outs, wdir, vars), результаты прогона в `dvc.lock`. Оба файла коммитятся в git. Данные лежат в кэше `.dvc/cache`, в гит не идут.

Состояние
- `dvc status` — какие стадии устарели (изменились deps или outs). Смотреть перед любым пересчётом.
- `dvc dag` — граф стадий.
- `dvc diff` — что изменилось в данных относительно гита.

Пересчёт
- `dvc repro [файл:стадия]` — пересчитать устаревшее. Указанная стадия тянет за собой устаревшие стадии выше по графу.
- `-s` (`--single-item`) — только эту стадию, без зависимостей. `-f` — принудительно. `-R папка` — все `dvc.yaml` в папке.
- `--no-commit` — прогнать, но не записывать в кэш и `dvc.lock`, пока результат не проверен.
- `outs: [путь: {persist: true}]` — выход не удаляется перед прогоном (кэши по элементам внутри скрипта).

Лок и фиксация (не путать)
- «Залочить» стадию = `frozen: true` в `dvc.yaml`, команда `dvc freeze <стадия>`, обратно `dvc unfreeze`. DVC перестаёт смотреть на её deps и никогда не пересчитывает, `dvc status` показывает только предупреждение. Для дорогих и уже посчитанных стадий.
- `dvc commit <стадия>` — принять текущее состояние: записать в `dvc.lock` хэши deps и outs и положить результат в кэш, команду не запускает. Нужно, когда изменился код или комментарий, а результат прежний, или результаты получены вручную. Для стадии с изменёнными deps или outs без `-f` откажет («unable to commit changed stage»): именно `-f` и нужен, чтобы принять руками правленые файлы без пересчёта. `-d` — вместе с зависимостями. Минус: DVC не гарантирует воспроизводимость, использовать, когда уверены в результате.
- Команды `dvc lock` в DVC 3 нет. `dvc.lock` — файл результатов, а не блокировка.

Данные и хранилища
- `dvc add файл` — взять файл под DVC без стадии (появляется `.dvc`-файл).
- `dvc remote add` и `dvc push` / `dvc pull` / `dvc fetch` — удалённое хранилище кэша: без него результат живёт только на этом диске.
- `dvc checkout` — вернуть из кэша файлы по версии из `dvc.lock`.
- `dvc gc` — чистка кэша от неиспользуемого. `dvc import-url` / `dvc get` — данные по ссылке или из чужого репозитория.
- `dvc config core.autostage true` — `dvc.lock` и `.dvc` сами попадают в `git add`.

Правила
- Платную стадию (вызов модели) не запускать без слова пользователя; уже посчитанную — замораживать или `dvc commit`, а не оставлять под пересчёт.
- Перед `dvc repro` — `dvc status`: не запускать каскад, который заденет дорогие стадии.
- После изменения `dvc.yaml` — коммит `dvc.yaml` и `dvc.lock` вместе.
